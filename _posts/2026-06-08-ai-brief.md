## 5. AI Failures & Lessons Learned

### Case 1: Air Canada Autonomous Booking Agent (January 2026)
Air Canada's autonomous booking agent **incorrectly rebooked 1,247 passengers** onto wrong flights during a Toronto weather disruption. The agent had performed well in testing but failed in production edge cases involving simultaneous high-volume disruptions.
**Lesson:** Production load scenarios and failure-mode testing must be explicitly scoped — testing environment parity is not sufficient for complex state machines.

### Case 2: Google AI + KPMG Parliamentary Inquiry (2026)
A team of Australian academics apologized after Google's AI chatbot made **damaging false accusations** about Big Four consulting firms — specifically claiming KPMG audited Commonwealth Bank during a planning scandal (KPMG had never audited that bank). The fabricated claim was then referenced in a parliamentary inquiry.
**Lesson:** AI-generated content that enters formal or legal contexts without human review creates compounding institutional risk. Hallucination-prone workflows need mandatory human-in-the-loop gates at high-stakes output points.

### Case 3: Microsoft Recall Opt-In Reversal (June 2026)
Microsoft reversed course on Recall (AI-powered screen recording/recall feature), making it **opt-in** rather than on-by-default ahead of its June 18 launch, after significant backlash.
**Lesson:** Default-on AI features that capture sensitive data face high user trust barriers. Product teams must model consent and privacy concerns early, not as launch-gate considerations.

### Systemic Failure Data (Kiteworks Research, 2026)
- **65% of organizations** experienced at least one cybersecurity incident caused by AI agents in the past year.
- Of AI agent incidents: **61% involved sensitive data exposure**, 43% caused operational disruption, 41% resulted in unintended cross-process actions.
- **70-95% of AI agent deployments** are currently failing in production.
- Gartner (May 26, 2026): Uniform governance across AI agents will cause enterprise failures — differentiated governance by agent risk profile is required.

### How to Avoid These Failures
1. **Production != test**: Simulate high-volume, concurrent, and adversarial edge cases before go-live.
2. **Tiered governance**: Apply stricter oversight to agents with write-access or external communications.
3. **Mandatory human gates** at high-stakes output (legal, financial, external communications).
4. **Default-off for sensitive features**: Opt-in > opt-out for data-capture and high-agency features.
5. **Scope creep monitoring**: Agent action logging and anomaly detection are non-negotiable for production.

## 6. AI Evals — Latest Tools, Methods & Examples

### What's New in Evals (2026)
The field has shifted decisively from one-off benchmark testing to **CI/CD-integrated continuous evaluation** — evals run automatically on every deployment, catching regressions before users do.

### Top Eval Tools

| Tool | Strengths | Best For |
|---|---|---|
| **DeepEval** | Open-source, 50+ research-backed metrics, RAG + agents + chatbots | Teams wanting full coverage without vendor lock-in |
| **Confident AI** | Removes engineering bottlenecks, 50+ metrics, safety evals | Enterprises scaling eval infrastructure |
| **LangSmith** | Native LangChain/LangGraph integration, tracing + eval together | Teams on LangChain stack |
| **Braintrust** | Excellent CI/CD integration, good for regression testing | Eng teams with mature CI pipelines |
| **Ragas** | Specialized RAG evaluation | Retrieval-augmented generation systems |
| **Weights & Biases (Weave)** | Experiment tracking + evals unified | ML-heavy teams tracking model iterations |

### Key Eval Dimensions (AWS Guidance, 2026)
For agent evaluation, assess simultaneously across:
1. **Response quality** (factual accuracy, relevance, completeness)
2. **Latency** (time-to-first-token, total completion time)
3. **Cost** (tokens consumed per task)
4. **Safety** (policy compliance, sensitive data handling)
5. **Tool use accuracy** (correct tool invocation, parameter precision)

### Best Practices
- **Use the same scoring framework** for offline and online evals — inconsistencies between pre-deploy and production metrics are a reliability red flag.
- **Calibrate LLM graders against human review** — automated graders need periodic calibration to prevent score drift.
- **Monitor distribution drift** — post-launch, track whether input distributions shift from what was evaluated during development.
- **Eval agents as trajectories, not just outputs** — the AgentRx paper (Feb 2026) proposes diagnosing failures from execution trajectories, not just final answers. This is especially important for multi-step agents.

### Practical Example: RAG Eval with Ragas
```python
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision

results = evaluate(
    dataset=your_dataset,
    metrics=[faithfulness, answer_relevancy, context_precision]
)
# faithfulness: Are claims grounded in retrieved context?
# answer_relevancy: Does the answer address the question?
# context_precision: Is retrieved context actually needed?
```

### Practical Example: Agent Trajectory Eval with DeepEval
```python
from deepeval import evaluate
from deepeval.test_case import LLMTestCase
from deepeval.metrics import ToolCorrectnessMetric, TaskCompletionMetric

test_case = LLMTestCase(
    input="Book me the cheapest flight from ORD to JFK next Tuesday",
    actual_output=agent_response,
    tools_called=agent_tool_calls,
    expected_tools=["search_flights", "compare_prices", "book_flight"]
)
evaluate([test_case], [ToolCorrectnessMetric(), TaskCompletionMetric()])
```
